# SPEC — Cycle 0017: Teacher-Driven URL Broadcast + Student Follow / Re-Sync

## WHY
A teacher can activate a resource (cycle 0016) and every student sees it render in the shared `ResourcePane` iframe — but that pane is frozen at the resource's *original* URL. There is no way for the teacher to advance position. For a slide deck (e.g. slides.com) where each slide is its own route, the teacher cannot move the room from slide 3 to slide 4: the only "navigation" available is activating an entirely different resource. Cross-origin iframes hide their internal navigation, so Blended cannot follow the teacher by reading the iframe; it must *own* the broadcast position as explicit state (ADR-0002). Today that state (`sessions.currentUrl`) is written exactly once, at activation, and never moves. Worse, a student who clicks or scrolls inside their own iframe drifts away from the room with no way to be pulled back.

## CONCRETE USER BENEFIT
Mid-session, a teacher types or pastes the next slide's URL into a broadcast field (or it is set via the active resource) and clicks **Broadcast**; every connected student's iframe snaps to that URL in realtime, with no reload and no shared link to paste. A student who has clicked or scrolled away inside their own iframe is pulled back to the teacher's position on the very next broadcast — even if the teacher re-broadcasts the *same* URL the student wandered from. A student who joins late lands directly on the teacher's current broadcast position, not the resource's first page. This is the first time a teacher can *advance the room through* a resource rather than merely choosing which resource is shown.

## USABLE END-STATE
On the teacher facilitation view (`/dashboard/sessions/[id]`), once a resource is active a **current-URL broadcast control** appears: a URL field plus a Broadcast action. Submitting a valid `http`/`https` URL updates the session's broadcast position and appends a URL-change event; the shared `ResourcePane` (teacher's own and every student's) reloads its iframe to that URL live. Every broadcast — including re-broadcasting the URL a student has locally navigated away from — forces the student's iframe to re-snap to the teacher's URL. A late-joining student immediately renders the current broadcast URL. An invalid/blank/unsafe URL, a broadcast attempted by a non-teacher, or a broadcast attempted with no active resource is rejected before any write, surfaced inline, and leaves the broadcast position unchanged.

## Objective
This cycle delivers the teacher-driven URL-broadcast vertical slice on top of cycle 0016's activation pane: a new sanctioned write path (`broadcastResourceUrl` / `buildResourceUrlChange`) that appends a `ResourceUrlChanged` event and updates the session's `currentUrl` plus a fresh per-broadcast `currentUrlVersion` token in one transaction; a teacher-side current-URL control in `SessionLifecycle` that validates through the existing `validateResourceUrl` seam before writing; and a version-keyed `ResourcePane` iframe so every broadcast remounts the frame and re-syncs locally-navigated students. It makes the teacher's *position within* an active resource — not just the choice of resource — the shared, realtime, late-joiner-hydrated state Blended owns, per ADR-0002.

## Scope

### In Scope
- **Broadcast write path**: `broadcastResourceUrl` / `buildResourceUrlChange` in `src/lib/sessions.ts` — the sole sanctioned URL-broadcast path — routing a dual-write through `writeEvent('ResourceUrlChanged', …)` that sets `sessions[id].currentUrl` and a fresh per-broadcast `currentUrlVersion` token in one transaction; the additive `sessions.currentUrlVersion` schema field (`src/lib/db.ts`); the `applyEvent('ResourceUrlChanged', …)` fold (stores `currentUrl`/`currentUrlVersion`, tolerant of an absent prior session); and stamping `currentUrlVersion` on the existing `ResourceActivated` write/fold so activation and broadcast share one re-sync key.
- **Teacher broadcast control**: a current-URL field + Broadcast action in `SessionLifecycle` (`src/components/SessionLifecycle.tsx`), enabled only when the session has an active resource, gating the URL through `validateResourceUrl` before any write and surfacing rejections inline.
- **Version-keyed re-sync in `ResourcePane`**: the shared iframe's React `key` is derived from `currentUrlVersion` so every broadcast (including re-broadcasting an identical URL) forces a fresh iframe mount, snapping locally-navigated students back; both `SessionLifecycle` and `StudentSession` pass the new prop. Late-joiner hydration is inherited from the session row (no new query).

### Out of Scope
- **postMessage / provider embed-API capture** so the teacher can sync by clicking *inside* the deck (explicit ADR-0002 Batch-2 spike).
- **Prev/next stepping over a stored slide-URL list** — this cycle ships the current-URL field; a resource carrying an ordered list of slide URLs and prev/next controls over it is a sibling cycle.
- **Same-origin / "URL belongs to the active resource" restriction** on the broadcast URL — this cycle validates scheme-safety only (via `validateResourceUrl`); constraining the broadcast URL to the active resource's origin is deferred.
- **Blocked-embed fallback** for URLs that refuse to render in an iframe (separate issue) — the pane renders `currentUrl` directly and does not crash.
- Any permission-rule change — `currentUrl`/`currentUrlVersion` inherit the existing `sessions` owner-only-write rule (cycle 0003).

## Requirements
- **Single sanctioned path**: every broadcast MUST route through `broadcastResourceUrl` → `writeEvent('ResourceUrlChanged', …)`. No product code path writes `sessions[id].update({ currentUrl | currentUrlVersion })` outside this helper or the existing `activateResource` path (ADR-0001/ADR-0003 dual-write invariant).
- **Reuse the URL seam**: the broadcast URL MUST be validated through the existing `validateResourceUrl` (`src/lib/resources.ts`) — no inline scheme/`URL` parsing is introduced. A URL it rejects (`blank`, `unsafe_scheme`, `unparseable`) produces no write.
- **Pure, total builder**: `buildResourceUrlChange` validates input before producing any txn/envelope — requires `actor.role: 'teacher'`, present actor `userId`, present `sessionId`, a present `activeResourceId` on the live session (broadcast is only legal for a session with an active resource), and a `validateResourceUrl`-accepted URL. It mints a fresh `currentUrlVersion` token per broadcast and sets the envelope `actor.role: 'teacher'`. It produces no plan on invalid input (throws before any write).
- **Per-broadcast version token**: `currentUrlVersion` is a fresh unique token minted on each broadcast (and on activation), not a read-before-write counter — so two broadcasts never collide and no live-row read is required. It is the value `ResourcePane` keys its iframe on.
- **Atomic dual-write**: the `ResourceUrlChanged` envelope and the `sessions` projection update commit in one `db.transact()`; a rejected write leaves no partial state (no orphan event, unchanged `currentUrl`/`currentUrlVersion`).
- **Ownership in depth**: the write is admitted only for the owning teacher — enforced by the builder's role/actor check AND the existing data-layer `sessions` owner-only-write rule (`auth.id == data.teacherId`). No perms change.
- **Replay-safe fold**: `applyEvent` folds `ResourceUrlChanged` (sets the projection session's `currentUrl`/`currentUrlVersion`, tolerant of an absent prior session, keyed defensively) so the type never raises `UnknownEventTypeError` and `rebuildSessionProjection` stays whole. `SessionProjection.session` gains optional `currentUrlVersion?`.
- **Realtime, not polling**: broadcast changes propagate to all connected teacher/student views via the existing `db.useQuery` subscriptions over the session row, with no reload.
- **Re-sync on every broadcast**: because the iframe is keyed on `currentUrlVersion`, a broadcast re-snaps a locally-navigated student even when the broadcast URL equals the URL the student wandered from.
- **No email rendering**: the broadcast control and pane render resource/session URL fields only — never email (privacy stays structural).
- **Failure behavior**: On invalid input (non-teacher actor, missing session id, no active resource, blank/unsafe/unparseable URL), `buildResourceUrlChange` throws before any write and `currentUrl`/`currentUrlVersion` stay unchanged; the teacher UI surfaces the failure inline (`role="alert"`) + `console.error('[SessionLifecycle] …')` and retains the entered value for retry, never swallowed. On a rejected `db.transact()` (permission denial / network), the rejection propagates to the caller and is surfaced inline; no projection row is partially updated. When no resource is active, the broadcast control is disabled (no broadcast is possible) and the pane renders its existing explicit empty state. A broadcast URL that fails to load in the iframe is a deferred concern (blocked-embed fallback is out of scope) — the pane still points the iframe at `currentUrl` and does not crash.

## Acceptance Criteria
- [ ] A teacher with an active resource broadcasts a new URL and both the teacher view and every connected student view reload the `ResourcePane` iframe to that URL within the same session, with no reload of the page (user-observable benefit).
- [ ] Broadcasting appends exactly one `ResourceUrlChanged` event and sets `sessions[id].currentUrl` + a new `currentUrlVersion` (admin-observable: one event with a matching payload, projection row updated) in one transaction.
- [ ] **Re-sync**: after a student navigates locally inside their iframe, the next teacher broadcast re-syncs that student to the teacher's URL — including when the broadcast URL equals the student's locally-navigated URL (the version-keyed iframe remounts).
- [ ] A context that joins/loads after one or more broadcasts immediately shows the current broadcast URL, not the resource's original URL.
- [ ] **Failure path**: attempting a broadcast as a non-teacher actor, with no active resource, or with a blank/unsafe/unparseable URL throws in `buildResourceUrlChange` (or is gated by `validateResourceUrl`/a disabled control), writes no event, and leaves `currentUrl`/`currentUrlVersion` unchanged; the teacher UI shows an inline alert and logs to console rather than crashing.
- [ ] `applyEvent` folds `ResourceUrlChanged` without raising `UnknownEventTypeError`, and `rebuildSessionProjection` over a log containing activation followed by broadcasts reproduces the latest `currentUrl`/`currentUrlVersion`.
- [ ] All existing tests still pass.
- [ ] No compiler/linter warnings introduced (`npm run astro check` clean).

## Testing Strategy
- **Vitest** (pure logic, beside the module as `*.test.ts`): `buildResourceUrlChange` happy path (teacher broadcasting a valid URL on a session with an active resource produces the expected envelope + payload `{ sessionId, currentUrl, currentUrlVersion }` and a fresh version distinct from the prior one), and each rejection leg (non-teacher role, missing `sessionId`, no `activeResourceId`, and each `validateResourceUrl` rejection: blank, `unsafe_scheme`, `unparseable`) throwing before any plan. `applyEvent('ResourceUrlChanged', …)` fold: sets `currentUrl`/`currentUrlVersion`, tolerates an absent prior session; `rebuildSessionProjection` over `[ResourceActivated, ResourceUrlChanged, ResourceUrlChanged]` reproduces the latest URL + version. Assert injectable version-minting is deterministic in tests (mirroring the `generateJoinCode` injectable-RNG pattern).
- **Playwright** (`e2e/broadcast-resource-url.spec.ts`, skips loudly without `INSTANT_ADMIN_TOKEN`): Teacher (context A) activates a resource, then broadcasts a slide-3 route; Students (contexts B, C) iframes show slide-3 with no reload. Student B navigates its iframe locally to slide-5; Teacher broadcasts slide-4; assert B and C are both on slide-4. A late context D joins mid-session and lands on the teacher's current broadcast URL. Admin observability asserts one `ResourceUrlChanged` event + updated `sessions` projection per broadcast; the failure leg (non-teacher / blank-URL) asserts no event written and `currentUrl`/`currentUrlVersion` unchanged.
- E2E coverage is required because this cycle ships observable UI (`src/components/`) — the broadcast control and the version-keyed iframe re-sync must be exercised in-browser across contexts.
