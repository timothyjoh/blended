# Research: Cycle 0017

## Cycle Context
SPEC 0017 adds a teacher-driven URL broadcast vertical slice on top of cycle 0016's activation pane. It requires: (1) a new sanctioned write path `broadcastResourceUrl` / `buildResourceUrlChange` in `src/lib/sessions.ts` that dual-writes a `ResourceUrlChanged` event and updates `sessions[id].currentUrl` plus a fresh per-broadcast `currentUrlVersion` token in one transaction, gated on a teacher actor, present session id, a present `activeResourceId` on the live session, and a `validateResourceUrl`-accepted URL; (2) an additive `sessions.currentUrlVersion` schema field and an `applyEvent('ResourceUrlChanged', …)` fold, with `currentUrlVersion` also stamped on the existing `ResourceActivated` write/fold; (3) a teacher-side current-URL broadcast control in `SessionLifecycle` (enabled only when a resource is active, validating through `validateResourceUrl` before any write); and (4) a version-keyed `ResourcePane` iframe (React `key` derived from `currentUrlVersion`) so every broadcast remounts the frame and re-syncs locally-navigated students, with both `SessionLifecycle` and `StudentSession` passing the new prop. The state is realtime via existing `db.useQuery` subscriptions; late joiners hydrate from the session row. No permission-rule change (inherits the cycle-0003 `sessions` owner-only rule).

### Existing Patterns to Follow
- **Pure-core / thin-wrapper split**: every sanctioned write is a total pure builder (`build*`) that validates and throws BEFORE producing any plan, plus a thin async wrapper (`write*`) that routes the dual-write through `writeEvent`, plus an exported `default*Txn`. Builder validation order: `actor.role !== 'teacher'` → missing `actor.id` → missing `sessionId` → missing target → URL/belonging check — `src/lib/sessions.ts:988-1009` (activate), `860-902` (queue).
- **Builder error-message convention**: `throw new Error('<fnName>: <reason>')` (e.g. `'activateResource: only a teacher may activate a resource'`); tested via `.toThrow(/regex/)` — `src/lib/sessions.ts:989-1001`.
- **`writeEvent` dual-write choke point**: appends a `sessionEvents` envelope + caller projection txns in ONE `db.transact()`; requires a non-empty `projectionTxns` array; validates `type`, `sessionId`, `actor.role` (must be in `ACTOR_ROLES`), integer `schemaVersion`; throws synchronously on bad input, writes nothing; returns the `db.transact()` promise (rejection propagates) — `src/lib/db.ts:583-621`.
- **Envelope `WriteEventMeta` shape**: `{ sessionId, actor: { id, role }, payload }`; builders hard-set `actor: { id: teacherId, role: 'teacher' }` — `src/lib/sessions.ts:1003-1008`.
- **Injectable-determinism pattern for minting** (the pattern SPEC names for the version token): `generateJoinCode(randomBytes = defaultRandomBytes)` injects a CSPRNG source so the pure core is deterministic under an injected source in tests; builders also accept injectable `id?`/`now?` — `src/lib/sessions.ts:29-44`, `83-90`, `872-885`.
- **`applyEvent` fold conventions**: each case keyed by `payload.<id> ?? event.id`, defensive type-guarded defaults, never mutates input (spreads a new projection), tolerant of absent prior session by building a minimal one from the payload; mutating-an-existing-session cases mirror `SessionStarted`/`SessionEnded`/`ResourceActivated` (`prev ? { ...prev, … } : { minimal }`) — `src/lib/db.ts:324-343`, `494-523`.
- **Failure handling**: builders throw before any write (no partial state); wrappers do NOT catch a rejecting `writeEvent` (rejection propagates to the caller); a rejected `db.transact()` fails atomically (event + projection commit together) — `src/lib/sessions.ts:1032-1041`, `src/lib/db.ts:619-620`. Component handlers wrap the wrapper call in `try/catch`, set an inline error string, and `console.error('[SessionLifecycle] …', err)` in the catch, retaining entered values; a per-action pending latch suppresses double-submit — `src/components/SessionLifecycle.tsx:125-199`.
- **Component validation-before-write**: the add-resource handler gates the URL through `validateResourceUrl` and maps each rejection reason to inline copy + `console.error` BEFORE calling the wrapper — `src/components/SessionLifecycle.tsx:134-145`.
- **Observability**: the structured event log IS the `sessionEvents` envelope written by `writeEvent` (`type`, `actorId`, `actorRole`, `occurredAt`, `receivedAt`, `payload`) — `src/lib/db.ts:607-617`. UI surfaces errors inline via `role="alert"` testids + `console.error('[SessionLifecycle] …')` / `console.error('[StudentSession] …')` — `src/components/SessionLifecycle.tsx:109-111`, `168`, `195`; `src/components/StudentSession.tsx:34-35`. (The cycle-engine `.cycle/log.jsonl` is harness telemetry, separate from product code.)
- **Idempotency / retry-safety**: the activation/queue paths are deliberately NOT idempotent — each call appends a fresh event; the projection update is convergent (keyed `sessions[id].update` re-sets identical values on re-activation). Per-broadcast `currentUrlVersion` is specified as a fresh unique token per call (mint, not read-before-write), so no live-row read is required and two broadcasts never collide — `src/lib/sessions.ts:1022-1041`. Component-level double-submit guard is a per-id pending latch (`activatingId` / `resPending` / `pendingId`) — `src/components/SessionLifecycle.tsx:103`, `180`, `548`.
- **Realtime, not polling**: every view subscribes via `db.useQuery` over the session row; a projection update re-renders all subscribers with no reload — `src/components/SessionLifecycle.tsx:75`, `src/components/StudentSession.tsx:25`.
- **No-email invariant**: panes/controls render resource/session URL fields only; privacy is structural (no `email` field on the rendered entities) — `src/components/ResourcePane.tsx:10`, `src/lib/db.ts:92-97`.

## Open Questions
- **Version-token source**: SPEC requires a "fresh unique token minted on each broadcast … (mirroring the `generateJoinCode` injectable-RNG pattern)" but does not pin the concrete generator (e.g. `id()` from `@instantdb/react` vs a dedicated `generateUrlVersion` over an injectable source). The plan must choose the mint function and its injectable seam for deterministic tests.
- **`ResourceActivated` payload/fold change**: stamping `currentUrlVersion` onto the existing activation write changes the `ResourceActivated` envelope payload and `applyEvent` case; whether existing activation unit/fold fixtures (`src/lib/sessions.test.ts:1265-1276`, `src/lib/db.test.ts:174-193`, `445-483`) are updated in place or augmented is a plan decision.
- **Broadcast control placement & testids**: SPEC mandates "new fixed testids" for the broadcast field/action and disabled state but does not enumerate the exact strings or whether the control sits in the "Active resource" card (`src/components/SessionLifecycle.tsx:373-384`) or elsewhere; the plan must fix the testid names and DOM location.
- **`ResourcePane` key derivation**: whether the iframe `key` is `currentUrlVersion` alone or a composite (e.g. `activeResourceId` + `currentUrlVersion`), and the fallback when `currentUrlVersion` is absent on a pre-0017 session row, is unspecified.
